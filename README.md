# LG Aimers 9th · 투구 제구 성공 확률 예측

투구 직전의 경기 상황과 과거 이력을 활용해 `control_success = 1`일 확률을 예측한 **떡잎마을방범대**의 팀 프로젝트입니다. 시간 순서 검증, 평가 행 독립성, 실험 재현성을 중심으로 모델을 개발했습니다.

이 저장소는 대회 연구에서 **공통 전처리 코드와 합성 데이터 테스트를 선별한 포트폴리오**입니다. 모델링 과정은 문서로 소개하며, 최종 제출 앙상블과 학습 산출물은 포함하지 않습니다.

## 핵심 설계

- **정보의 사용 시점 명시:** 예측 연도 이전의 이력을 사용하고, 학습 통계와 범주 사전은 `fit`에서 고정합니다.
- **평가 행 독립성:** 같은 행의 피처가 다른 평가 행의 포함 여부나 입력 순서에 따라 변하지 않도록 설계했습니다.
- **시간에 따른 성능 변화 확인:** 과거 연도로 학습하고 다음 연도를 검증하는 방식으로 단일 평균 점수에 가려지는 변동을 확인했습니다.
- **성능과 실행 가능성 분리:** 후보의 검증 성능과 제출 패키지의 계산 일치성을 각각 확인했습니다. 실행 검증을 통과했더라도 성능이 부족한 후보는 예비안으로 남겼습니다.

```text
학습 행 + 이전 연도 이력
          │ fit: 통계·이력 조회표·범주 사전 고정
          ▼
투구 직전의 한 행 → transform → 표 형식 피처 / 수치·범주 텐서
                                      │
                                      └─ 후속 모델의 입력
```

공개 구현과 테스트의 범위는 [설계 설명](docs/methods.md), 연구 과정의 선택과 한계는 [대표 실험](docs/experiments.md)에 정리했습니다.

## 빠르게 확인하기

NumPy·pandas 의존성 설정은 [실행 안내](docs/reproduction.md)를 참고하세요. 저장소 루트에서 다음 명령을 실행합니다.

```bash
python -m unittest discover -s Preprocess/tests -v
python tools/check_publication.py
```

첫 명령은 코드로 생성한 합성 입력으로 전처리 계약을 확인하고, 두 번째 명령은 공개 파일 구성을 점검합니다. 대회 데이터나 GPU 없이 실행할 수 있습니다. 이 검사는 모델 성능이나 최종 제출 점수를 재현하지 않습니다.

## 배운 점과 한계

연도별 성능 차이를 확인하면서, 평균 점수 개선만으로 모델을 선택하기 어렵다는 점을 배웠습니다. 여러 seed의 평균도 모든 연도에서 개선을 보장하지 않았으며, 이미 반복 관찰한 검증 연도는 새로운 미관측 평가처럼 해석할 수 없었습니다.

이 공개본으로 확인할 수 있는 것은 **전처리의 구조와 합성 입력에서의 동작**입니다. 원본 데이터, EDA 노트북, 전체 실험 코드, 학습 가중치, 선수별 조회표, 예측값과 제출 ZIP은 원본 연구 저장소에 보존하며 여기에는 추적하지 않습니다. 따라서 대회 전체 파이프라인과 리더보드 점수의 완전한 재현은 제공하지 않습니다.

로컬 파일과 노트북 출력은 삭제하지 않으며, [`.gitignore`](.gitignore)로 업로드 대상에서 제외합니다.

팀 단위의 연구 기록이며, 개별 기여나 코드 권리를 임의로 특정하지 않습니다. 자세한 출처와 이용 범위는 [기여·출처](docs/attribution.md)를 참고하세요.
