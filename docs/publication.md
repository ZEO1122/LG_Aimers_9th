# 공개 범위와 로컬 파일 보존

## 현재 배포 방식

기존 연구 저장소와 그 Git 이력은 Private으로 보존한다.
이 포트폴리오는 별도의 Git 이력으로 시작하며, 전처리 소스·합성 테스트·설명 문서만 추적한다.
원본 파일이나 노트북 출력은 삭제하지 않는다. 로컬 연구 파일은 `.gitignore`로 업로드에서 제외한다.

| Git 포함 | 로컬 보존 / Git 제외 |
|---|---|
| `Preprocess/common/*.py`, 전처리 테스트·진입점 | `data/`, `EDA/`, `Experiment/`, `artifacts/`, `private/`, `local/` |
| 선별한 Markdown 문서 | 노트북 전체, 실행 출력, 원본 행, 선수별 통계 |
| 업로드 검사·CI·의존성 목록 | 모델·lookup·예측·압축파일·로그·이미지·문서 첨부 |

`.gitignore`는 이미 추적된 파일과 과거 커밋을 숨기지 않는다.
`tools/check_publication.py`는 Git 추적 파일도 검사하므로 `git add -f`로 추가된 제외 파일도 오류로 보고한다.
이 검사는 파일을 지우거나 Git index에서 제거하지 않는다. 오류가 나면 게시를 중단하고 해당 변경을 검토한다.
검사 대상은 작업 폴더의 파일 내용이므로 push 직전에는 staged 내용도 확인해야 한다.
CI는 push 이후에 실행되며, 이 검사 자체가 Git 업로드를 강제로 막는 것은 아니다.
현재 파일만 검사하므로, 향후 이력이 쌓인 뒤에는 과거 커밋·브랜치·PR·릴리스·Actions 로그도 별도로 확인해야 한다.

## Public 전환 전에 확인할 사항

2026-09-08에 확인한 [공식 동의사항](https://dacon.io/competitions/official/236743/overview/agreement)은
대회 데이터의 대회 외 사용과 비참가자에 대한 재배포를 제한한다. 코드 공유에도 DACON 플랫폼을 통한 공유 조건이 있다.
데이터 제외만으로 GitHub 공개 권한이 자동 확정되는 것은 아니다.

1. 자체 작성 코드와 수행 과정 설명의 GitHub 공개 허용 범위 및 DACON 동시 게시 필요 여부를 운영진에게 확인한다.
2. 공동 작성 코드와 팀원 표시 범위에 대해 팀의 동의를 확인한다.
3. 외부에서 가져온 코드의 출처와 라이선스 조건을 확인한 후 필요한 고지를 추가한다.
4. 최종 제출 ID·ZIP 해시·소스 버전·리더보드 점수를 연결한 뒤 결과 표기를 확정한다.

확인 전에는 이 레포도 Private으로 유지한다. 이 문서는 운영진 승인이나 팀 동의를 대신하지 않는다.
현재는 코드 전체에 MIT 등의 새 라이선스를 부여하지 않았다. 공개 열람과 재사용 허용은 별도 문제다.

운영진 문의 시 사용할 문안:

> 대회 원본 데이터, 학습 가중치, lookup, 예측 및 노트북 출력물을 제외한 자체 작성 코드와 수행 과정 설명을
> GitHub 포트폴리오에 공개해도 되는지 확인 부탁드립니다. DACON 코드 공유 게시판에도 함께 게시해야 하는지,
> 내부 검증 지표 요약의 공개 범위도 안내 부탁드립니다.

이 문안은 초안이며 운영진에게 전송하지 않았다.
